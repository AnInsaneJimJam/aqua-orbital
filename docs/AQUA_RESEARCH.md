## 3. Exact Aqua boundary

These are upstream ABI signatures, not proposed new functions:

```solidity
function ship(address app, bytes calldata strategy, address[] calldata tokens,
    uint256[] calldata amounts) external returns (bytes32 strategyHash);
function dock(address app, bytes32 strategyHash, address[] calldata tokens) external;
function pull(address maker, bytes32 strategyHash, address token,
    uint256 amount, address to) external;
function push(address maker, address app, bytes32 strategyHash,
    address token, uint256 amount) external;
function rawBalances(address maker, address app, bytes32 strategyHash, address token)
    external view returns (uint248 balance, uint8 tokensCount);
function safeBalances(address maker, address app, bytes32 strategyHash,
    address token0, address token1) external view returns (uint256 balance0, uint256 balance1);
```

`ship` hashes the supplied bytes as `keccak256(strategy)`. The allocation key is `(msg.sender, app, strategyHash, token)`. `ship` initializes registry allowances without transferring or escrowing tokens. The `Shipped` event publishes strategy bytes, and `Pushed` events also occur during initialization; an indexer must not treat every `Pushed` event as an actual ERC-20 transfer. [Aqua implementation](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/Aqua.sol)

Each entry stores a `uint248` amount and `uint8` token count. `0` means uninitialized and `255` means docked; the maximum usable list length is 254. `safeBalances` reverts if either requested token is inactive/docked. App validation must impose its stricter immutable canonical token set, lengths, distinctness, token contracts, and positive supported allocations; do not assume Aqua validates an application's economic configuration. [IAqua](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/interfaces/IAqua.sol), [balance storage](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/libs/Balance.sol)

`pull` uses `msg.sender` as the app key. It decreases that app's allocation and calls ERC-20 `transferFrom(maker, to, amount)` through SafeERC20; the maker approves **Aqua**, not the Orbital router, for this output transfer. A different app cannot pull this allocation. `push` is permissionless for an active allocation: it increases the specified app's allocation and transfers tokens from its caller directly to the maker using Aqua's token allowance. It is not restricted to the app. [Aqua pull/push](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/Aqua.sol)

`dock` is maker-called, checks each entry's stored token count against the supplied list length, sets each entry to zero/docked, and transfers no ERC-20s. A duplicate token in a nonempty valid-size list reverts on its second visit because the first visit already wrote the docked sentinel. These count checks do not validate an app's canonical immutable token list; the app and UI must check the exact list and every registered token's activity. A docked entry cannot be shipped again under the same maker/app/hash because `ship` requires a previously zero token-count sentinel. New configurations use a new hash. Aqua does not call an app initialization/teardown callback. An app's own persistent state must have its own explicit lifecycle. [Aqua lifecycle](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/Aqua.sol)

## 4. Exact SwapVM boundary and the multi-token blocker

Upstream order and callable interfaces:

```solidity
struct Order { address maker; MakerTraits traits; bytes data; }
function hash(Order calldata order) external view returns (bytes32);
function quote(Order calldata order, uint256 amount, bytes calldata takerTraitsAndData)
    external view returns (uint256 amountIn, uint256 amountOut, bytes32 orderHash);
function swap(Order calldata order, uint256 amount, bytes calldata takerTraitsAndData)
    external payable returns (uint256 amountIn, uint256 amountOut, bytes32 orderHash);
```

The actual implementation's `quote` is not declared `view`, while `ISwapVM.quote` is `view`: interface-mediated static calls are supported. `quote` constructs the same instruction context with `isStaticContext = true`; `swap` uses false. Custom stateful instructions must skip all writes, logs, and transient writes on the static path. Call the view interface or explicitly `staticcall` when verifying quote purity. [ISwapVM](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/interfaces/ISwapVM.sol), [SwapVM quote/swap](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

In Aqua mode, `hash(order) = keccak256(abi.encode(order))`. Therefore maker registration ships **exactly `abi.encode(order)`** to Aqua, with `app = customRouter`, not `order.data`, not the program bytes alone, and not a different config struct. Maker traits set `useAquaInsteadOfSignature = true` (bit 254). Aqua mode skips the maker's EIP-712 signature and loads the pair's `safeBalances` under that order hash. Custom receivers for maker input and maker WETH-unwrapping are incompatible with Aqua mode. [SwapVM](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol), [MakerTraits](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/MakerTraits.sol)

**Critical integration fact:** current upstream SwapVM is pair-bound. `MakerTraitsLib.build` prefixes `order.data` with two sorted addresses; `quote` and `swap` call `order.traits.tokens(order.data)` and use only the taker's `isAToB` flag to reverse that fixed pair. The call ABI has no independent token-address arguments. A custom arithmetic opcode alone cannot honestly provide arbitrary pair trading within one n-token order unless token selection is deliberately extended. Creating a separate Aqua strategy hash per pair would fragment the n-token strategy and invalidate a single shared Orbital state. [MakerTraits builder](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/MakerTraits.sol), [SwapVM token selection](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

Recommended narrow fork: extract the duplicated token-resolution block into one `internal view virtual` resolver called by both quote and swap; the stock default preserves two-token behavior. The Orbital router overrides it using a pair of indices in authenticated-by-validation taker instruction arguments and the immutable registered token list committed by the order. Validate registration, the full canonical order/program, argument length, distinct indices, bounds, and order/config binding before choosing tokens or loading Aqua balances. Strip or consistently consume the pair prefix before other opcode arguments; specify the byte layout once and test the SDK against Solidity. This is a **project modification**, not an upstream extension point that already exists. Do not attempt to override stock `_dispatch` by inheriting the concrete Aqua router: its override is not `virtual`; use the upstream abstract `SwapVM` plus the app's dispatcher. [SwapVM](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol), [AquaSwapVMRouter](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/routers/AquaSwapVMRouter.sol)

## 5. Transfer flow and taker settings

For ordinary EOA exact-input trades, the recommended canonical taker settings are: `isExactIn = true`, nonzero 32-byte minimum-output threshold, a nonzero deadline, `allowPartialFill = false`, `isFirstTransferFromTaker = true`, `useTransferFromAndAquaPush = true`, WETH unwrapping false, no hook or callback data, no signature, and explicit recipient or the taker default. The fork's multi-token selector determines pair indices; freeze the unused direction bit to one canonical value rather than permitting ambiguous encodings. Use the upstream builder/decoder semantics: its header is 22 bytes, not a guessed 32-byte word. [TakerTraits](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/TakerTraits.sol)

With the `useTransferFromAndAquaPush` flag, SwapVM transfers gross input from taker to router, approves Aqua, and calls `AQUA.push` to transfer it from router to maker. Output is transferred through `AQUA.pull` from maker to the chosen recipient. Thus the taker approves the **custom router**, the maker approves **Aqua**, and the router temporarily handles input settlement without becoming the LP custody account. Protocol-fee instructions can change the pushed amount; exclude them in the canonical Orbital program if the app promises direct-to-maker LP fees only. Retain upstream settlement and per-order transient reentrancy locking; harden supported token delta checks in the fork where required by the original specification. [SwapVM transfer functions](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

The alternative flag-off branch expects an already increased Aqua input balance, normally through a callback. Exclude that path from Orbital's canonical program entry rules; it adds a second funding path and timing complexity without a requirement. Fail the quote and swap for disallowed callbacks/traits before running the economic engine. [SwapVM `_transferIn`](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

## 6. Custom instructions: what actually executes

The VM parses each instruction as a one-byte opcode, a one-byte argument length, then that many bytes. One instruction's arguments cannot exceed 255 bytes. Full n-token/tick configs cannot simply be placed inside a single opcode argument; place a 32-byte immutable config identifier there and keep validated registration data in app storage, with the full config independently available through registration calldata/events. Program, config hash, application address/domain, and nonce must bind to the same order. [VM run loop](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/VM.sol), [InstructionBuilder](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/InstructionBuilder.sol)

The upstream extension is compile-time dispatch: `SwapVM._dispatch(Context memory,uint256,bytes calldata)` is abstract; `AquaOpcodes._runOpcode` is an `if/else` table dispatching to libraries' internal `exec` functions. There is no universal onchain opcode registration function. A custom deployed router must include an app dispatcher and the new instructions in its compiled bytecode. Current opcode bank `0x50..0x6f` holds swap curves, with `0x52` unused; `0x90..0xaf` holds balance adjustments, with `0x92` unused. Do not allocate reserved `0xf0..0xff`. Freeze exact byte assignments in the project and test they do not collide at the pinned upstream commit. [AquaOpcodes](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/opcodes/AquaOpcodes.sol), [OpcodeList](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/OpcodeList.sol)

The `Context` contains the static flag, PC, program and taker-args pointers, a query `(orderHash, maker, taker, tokenIn, tokenOut, isExactIn)`, four swap registers `(balanceIn, balanceOut, amountIn, amountOut)`, and protocol-fee metadata. Current README diagrams mention a fifth register that the inspected source does not have; source wins. Stateful instructions can use internal router storage through a dedicated namespace, demonstrated by `Decay.store()`/`Decay.exec()`. Namespace app state independently; key it by maker and order hash, and never modify another opcode's namespace. [VM structs](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/VM.sol), [Decay instruction](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/instructions/Decay.sol), [storage slots](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/StorageSlots.sol)

Coordinator-selected program: exactly two custom instructions, `OrbitalFeeIn` at free fee opcode `0x72`, followed by terminal `OrbitalSwap` at free curve opcode `0x52`. The fee wrapper loads the immutable fee/config, saves gross `ctx.swap.amountIn`, computes the specified ceil-rounded raw fee once, subtracts it, and calls `ctx.runLoop()` to execute the curve with net input. The curve validates the registered state/program, runs the certified engine, sets `amountOut`, and commits principal/geometry only when `!ctx.vm.isStaticContext`. It does not reconstruct gross input or charge fees. When the nested loop returns, the wrapper restores the saved gross input and updates cumulative raw fee accounting only in nonstatic mode. An unexpected changed net amount or nonterminal curve execution reverts. The exact canonical program prevents repeated wrappers, repeated curves, added fee instructions, jumps, or external calls. Both libraries execute in router storage; stock settlement occurs after the outer loop and any later trait check or transfer revert also reverts both instructions' writes. [VM run loop](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/VM.sol), [SwapVM swap settlement](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

The wrapper shape follows upstream `FeeFlatIn`, whose denominator is **10,000,000**, despite the variable name `feeBps`; the existing Orbital spec uses **1,000,000 ppm**. The custom wrapper deliberately preserves the spec's ppm contract and keeps maker fees outside curve principal. Never also run stock `FeeFlatIn`, charge two fees, or recompute a fee per crossing. Encoding and config binding for both custom instructions must be frozen by the master prompt and tested; 32-byte config-hash arguments fit the VM's length constraint. [FeeFlatIn](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/instructions/FeeFlat.sol)

Alternative extension `Extruction` calls a maker-selected external contract and can return modified registers and PC; static mode uses a view interface. It does not return a modified `SwapQuery`, so it does not solve the pair-selection limitation. It also does not provide the requested custom deployed opcode by itself. The dedicated Orbital dispatcher is the clearer chosen integration. [Extruction](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/instructions/Extruction.sol)

## 7. Economic adaptation required from the existing specification

The repository's original specification assumes custody in one pooled `OrbitalPool`, multiple LP owners sharing tick radius, a permanently locked anchor, mint/burn, and fee escrow. Aqua's actual balances and token transfers are separated by maker/app/hash. A registry allowance is not a pooled vault deposit or an enforceable cross-maker claim. This follows directly from the allocation key and pull implementation. [Aqua](https://github.com/1inch/aqua/blob/9c5c42e5840e8741fba3597c48456c9510212b66/src/Aqua.sol)

Recommended project decisions, to be made normative in the master prompt:

1. One maker owns one complete strategy containing the immutable token set and a bundle of nested Orbital ticks. Its ticks aggregate into one Orbital invariant; separate makers are separately quoted strategies. The UI can select the best full-size quote across a bounded number of makers. Do not describe this as one atomically pooled invariant across all makers.
2. Keep a positive full-range anchor **inside each active strategy's immutable bundle**, preserving the solver's positive-interior-radius assumption. It is not permanently locked capital: maker may revoke Aqua allowances or dock the entire strategy. The maker can change size/ranges by retiring the old order and registering/shipping a new nonce/config; no in-place cross-maker mint/burn or fee-growth accounting is needed.
3. Store curve principal and geometric aggregates in Orbital state. After a successful trade, principal increases by net input and decreases by output; Aqua input allocation increases by gross input, and output allocation decreases by output. LP fee belongs to the maker immediately in their wallet, outside curve principal. A cumulative earned-fee counter is analytics, not an escrow liability or a separate collectible claim.
4. A maker's wallet balances and allowances can change independently; another app can spend shared wallet liquidity while this strategy's Aqua allocation remains unchanged. A quote may therefore be stale or unfundable. Check output funding/allowance and simulate before submission, but treat the atomic transfer as final authority; failure reverts Orbital writes and fees. Never use wallet balances as curve principal or promise reserved custody.
5. Direct `Aqua.push` donations can increase this strategy's allowance. Accept harmless surplus without changing prices or tick radii: compare Aqua allocation against the minimum app-accounted principal plus cumulative strategy-retained fee allocation, not exact equality. Because this release has no separate fee-pull path, fee allocation increases on swaps and remains within Aqua's raw allowance; it is still not an escrow claim or guaranteed wallet balance. Ignore excess for pricing. Otherwise a permissionless positive push can permanently grief the strategy. Do not automatically resynchronize the invariant to every observed Aqua balance.
6. Explicitly register configuration and initialize app state under maker authorization, using a fresh nonce and one-time order hash. Registration must bind the registered maker to `order.maker`, app address, chain/domain, canonical program/config hash, initial token amounts, and tick parameters. Aqua `ship` uses the same maker identity and exact order bytes. Mark app activation separately and permit it only after validating Aqua's active entries and starting allocations; maker-called register → approve → ship → activate is a resumable wallet sequence, not a fake atomic EOA batch.
7. An active order cannot reset its persistent geometric state. A docked/retired order hash is terminal. A replacement gets a fresh hash and newly certified initial state; change parameters through replacement. Quotes after docking fail on Aqua activity. A nonce in committed strategy bytes prevents stale state or pending quote replay into a new configuration.

These are design inferences from the source, not requirements stated by 1inch. The mathematics remains applicable within a maker's tick bundle; solvency, LP ownership, and fee semantics require the explicit changes above. A wallet owner withdrawing their own tokens is permitted in self-custody, so the UI must report unavailable liquidity without claiming theft prevention or guaranteed yield.

### Optional atomic USDC payment adapter

A thin separate payment adapter can be the SwapVM taker: pull the payer's approved input, approve the custom router, call the same `swap` with output recipient set to the adapter, then transfer the received USDC to an invoice merchant and any explicitly committed split recipient. Exact recipient allocation, input asset/amount, minimum total USDC, invoice ID, expiry, payer, merchant, and replay policy must be fixed in the project specification. Adapter execution is one nonreentrant transaction and uses the ordinary `transferFrom + Aqua.push` path without taker callbacks. The router sees the adapter as taker, so quote requests must use the adapter address as `from` and reproduce its actual recipient/traits. Do not silently use an EOA quote for a sender-sensitive canonical program. A failure in a later merchant transfer must revert the earlier Orbital swap and invoice-state changes. This follows from the upstream taker/recipient fields and atomic EVM settlement; it is a proposed app component, not a stock Aqua payment feature. [TakerTraits recipient](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/libs/TakerTraits.sol), [SwapVM settlement](https://github.com/1inch/swap-vm/blob/f09a41e689240adc645934f965c8061749397cd2/src/SwapVM.sol)

## 8. Required integration tests and unresolved verification

Write tests before modifying SwapVM:

- ABI/order hash parity: Solidity hash, SDK hash, and Aqua `Shipped.strategyHash` all match for exact order bytes; wrong app/hash/config/maker/chain/nonce rejected.
- Three-token strategy: all six directed pairs share one strategy hash and one geometric state, and output settlement uses the selected token rather than the original fixed pair prefix; legacy default pair resolver still matches pinned upstream tests.
- Maker approves Aqua; taker approves custom router; actual output maker→recipient, gross input taker→router→maker; router terminal token delta zero; LP fees excluded from principal.
- `staticcall` quote cannot write storage, emit logs, alter a nonce, initialize a strategy, or alter transient state; same-block quote/execution amounts and crossing certificates agree.
- Fresh lifecycle, incomplete shipping, missing token, malformed/duplicate token list, wrong initial amounts, double activation, docking, reordered/wrong docking list, same-hash reshipping failure, retired hash replay, and independent-maker isolation.
- External positive push leaves quote geometry unchanged; wallet depletion/revoked allowance, another app's successful spending, and replenishment produce explicit availability behavior and safe transfer failure/recovery.
- Callback/reentrancy attempt, disallowed partial/exact-output flags, opcode repetition/reordering/unknown opcode, malformed one-byte length, unauthorized protocol-fee opcode, rejected native value, and malicious token balance deltas.
- Full original mathematical differential/crossing tests within a maker strategy, especially inward-then-outward double crossings; no substitution of independent pair curves.

Unresolved onchain facts: chain-specific presence/source/code hash of official contracts on Arc, exact immutable values of any existing router, and selected chain EVM support for transient storage used by pinned SwapVM. These require the chain adapter's recorded RPC/source checks and a fork integration suite. No deployment, RPC bytecode verification, or executable Solidity test was performed during this research.
